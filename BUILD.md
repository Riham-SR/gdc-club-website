# Website Build Brief

## 1. Project Overview

Create a single-page website for the Graphic Design Club at St. Clair College.

The intended audience is students interested in graphic design, creative collaboration, skill development, and club participation.

The website will introduce the club, showcase student work, share tutorials and resources, present activities and upcoming events, and encourage students to get involved.

Additional artwork colours should remain intact.

### Typography

Use Inter for most text and Manrope for the Hero and About headings.

Preserve the verified font weights, sizes, line breaks, and hierarchy. Follow the tablet and mobile references for smaller-screen typography.

Do not apply one font or one heading size to every section.

### Spacing and Content Width

Use full-width section backgrounds with inner content aligned to the Figma reference.

Several desktop headings begin around 52 px from the left edge. Insets vary by section; do not assume one universal value.

Use flexible website layouts rather than absolute positioning for the entire page.

### Buttons and Reusable Components

Match the original:
- Navigation links
- Primary and secondary CTAs
- Tutorial cards
- Event cards
- Activity panels
- Arrows and numbered indicators
- Footer link groups

Verify padding, borders, corner radii, and button dimensions from their actual components before implementation.

Use:
- Semantic HTML
- CSS
- JavaScript only where necessary for interactions

Keep the project understandable and maintainable for an introductory web development workflow.

Do not add a framework, package manager, or dependency unless a genuine requirement is identified.

Proposed file organization:
- index.html
- css/styles.css
- js/script.js, if required
- assets/
- BUILD.md
- .github/copilot-instructions.md

Accessibility requirements:
- Use meaningful landmarks and a logical heading hierarchy.
- Provide useful alternative text for informative images.
- Give decorative images empty alternative text where appropriate.
- Use links for navigation and buttons for actions.
- Provide visible keyboard focus and accessible control names.
- Ensure menus and activity controls are keyboard accessible.
- Review text contrast and document any required design adjustment.
- Respect reduced-motion preferences if animation is implemented.

Confirm destinations and behaviour before implementing unresolved interactions.

## 7. Responsive Behaviour

Use the desktop, tablet, and mobile Figma frames as visual references.

Desktop:
- Match the 1440 px reference.
- Preserve the multi-column layouts and horizontal activity presentation.

Tablet:
- Follow the 768 px reference for section arrangements, typography, and navigation.
- Reference the Tablet Menu Overlay.

Mobile:
- Follow the 390 px reference for stacked content, image placement, typography, and navigation.
- Reference the Mobile Menu Overlay.

Across screen sizes:
- Preserve content order and priority.
- Scale images without distortion.
- Prevent unintended page-level horizontal overflow.
- Keep navigation and controls usable.
- Allow section heights to grow with content.
- Do not create the mobile layout by simply shrinking the desktop page.

Exact breakpoints and behaviour between reference widths are implementation decisions that still need to be documented.

## 8. Acceptance Criteria

The website is ready for review when:

- All eight required sections appear in the correct order.
- Content matches the approved Figma reference and documented decisions.
- Correct images, logos, icons, and fonts are used.
- Layout and hierarchy reflect the desktop, tablet, and mobile references.
- Typography, colours, spacing, borders, and image crops have been reviewed.
- Navigation and approved interactive elements work.
- Images, fonts, stylesheets, and scripts load correctly.
- The page has no unintended horizontal overflow.
- Keyboard navigation and focus states have been checked.
- The website has been previewed and compared with Figma.
- Remaining differences and known limitations are documented.
- Unresolved content or behaviour has not been silently invented.
